3. 摘要（Executive Summary）

一、Console 站 demo 重點

羅賓斯科技向富易達保經總經理張志成展示了 Console 業務員賦能後台的三大核心功能：

1. 保單管理 (OCR)：現場以一份 20 頁、包含印刷體與手寫字跡的壽險保單進行測試，系統在約一分鐘內完成辨識並抓取出要/被保人姓名、身分證號等關鍵欄位。此功能旨在解決保經公司行政人員每日需耗費大量時間手動 Key-in 新契約的痛點（約 5-10 分鐘/件），將其縮短至數秒。系統會提供一組「信心指數」（如 95%），作為輔助檢視的參考。最終產出的資料可匯出為符合富易達現有「創識」系統格式的 Excel 檔，實現快速上傳。

2. 長代碼系統：此為輕量化查詢工具，業務員輸入客戶車牌與身分證字號，即可查詢車籍資料、強制險與任意險到期日。此功能採「以量計價」模式（車籍 5 元、保險 5 元），旨在成為業務員聯繫既有客戶、進行再行銷的有效「敲門磚」。

3. 車險報價：此功能串接台產、富邦等保險公司，提供即時報價。然而，在會議中的兩次現場 demo（一次由 Leon 操作，一次應張總要求用其個資測試）均告失敗，未能成功拉取報價資料，引發張總對系統穩定性的嚴重關切。

二、SaaS 報價系統 demo 重點

團隊展示了針對富易達客製化的新版 SaaS 投保系統，以「旅平險」流程為例，強調三大優化：

1. 業務員流程整合：將過去紙本填寫的「業報書」（需求分析報告）完整數位化，整合於投保流程中。

2. 客戶體驗簡化：大幅簡化客戶端的操作，客戶收到連結後，僅需「3 次下一步、2 次打勾」，即可完成資料確認、條款閱讀並進入簽名付款頁面，流程可在數秒內完成。

3. 後台簡核機制：系統建置了符合富易達內部流程的線上簡核功能。案件在客戶付款、業務員簽署後，會進入富易達的簡核後台，由指定人員（如法遵或行政人員）進行最終審核、蓋上簡核章後，才正式送往保險公司。此機制確保了案件的合規性與正確性。

儘管流程展示順暢，張總仍提出具體優化建議，例如將業報書中多數客戶選擇相同的選項（如投保目的為「保障」）設定為預設值，以進一步提升業務員的操作效率。

三、富易達端 fit 評估與痛點討論

張總肯定羅賓斯的技術方向，並深入探討其在富易達的應用場景與挑戰：

1. 核心痛點確認：張總證實，富易達在全台 20 個據點約有 25-30 位行政人員，每月處理高達 7,000 件的產險單，其中新契約的 Key-in 作業是巨大的時間與人力成本。因此，OCR 技術確實切中要害，具備高度商業價值。

2. 系統整合是關鍵：富易達深度依賴「創識」作為核心營運系統，任何外部工具都必須與之無縫整合。張總對資料安全性（個資保護、ISO 認證）與系統串接的穩定性表達了高度關切。會議雙方同意，初期最務實的合作方式是透過「Excel 匯出/匯入」，待系統穩定且案件量提升後，再考慮投資進行 API 的即時串接。

3. 商業模式建議：張總提出具前瞻性的策略建議，認為羅賓斯不應只單獨與保經公司合作，而應直接與「創識」、「飛數」、「保經科技」等三大保經系統服務商洽談，將 OCR 技術作為模組植入其系統中。此 B2B2B 模式能快速擴大市場覆蓋率，並解決各家保經公司的共同痛點。

4. 穩定性壓倒一切：張總在會議中反覆強調，他無法接受讓自己的同仁使用不穩定的系統，並以「我不是白老鼠」表達其立場。車險報價功能的兩次 demo 失敗，嚴重影響了他對羅賓斯產品成熟度的信心。

四、商業條件與下一步

會議最終確立了雙方合作的推進框架與前提條件：

1. Console (OCR)先行：有鑑於遠見保經（同為創識系統用戶）已簽約導入 Console，張總希望先觀察其成效。羅賓斯承諾先提供 Console 測試帳號給張總，讓他親自體驗其穩定性與效益，並待遠見保經的導入專案順利運行後，再與富易達正式討論導入事宜。

2. SaaS 上線條件：張總明確指出，SaaS 系統若要對富易達業務員產生足夠的推動力，必須同時包含「旅平險」與「車險」兩大功能。僅有旅平險的方案，他將難以向內部交代與推廣。

3. 測試與驗收：羅賓斯承諾在系統（特別是車險報價）達到穩定狀態後，會提供測試帳號給張總與其核心同仁（Lana），讓他們親自完整操作一次流程，以收集最真實的回饋。

4. 推動保險公司：待羅賓斯內部技術問題解決後，下一步將是偕同張總，共同與台產的窗口（朱文錦）溝通，強力要求將車險與旅平險功能同步上線至正式環境，以滿足富易達的業務需求。
