3. 摘要（Executive Summary）

一、GCP 雲端架構討論重點

會議的起因是為了解決 SaaS 系統因 IAE（Insurance Agency Entity）切換機制複雜，導致新客戶「富易達」無法如期上線的問題。原計畫在現有架構下修改，但評估後發現風險高且耗時。

CEO Evin 提出一個更為徹底的解決方案：將羅賓斯科技的 SaaS 業務與羅賓斯保代的系統從 GCP 層級進行完全切割。具體作法是複製當前環境至一個全新的 GCP project，此新 project 將專屬於羅賓斯科技，而舊有的 GCP project 則完整移交給保代（或由股感接手管理）。此舉旨在從根本上解決兩家公司長期以來在雲端費用、系統權責上糾纏不清的問題。技術長 Leon 和股感 Loki 均同意此方向更為乾淨、長期來看更具效益。

二、SaaS 系統拆分可行性

技術層面上，與會者達成了拆分共識並討論了關鍵執行細節。遷移作業將不只是部署應用程式，而是包含一整套基礎設施的複製。重點項目包括：

1. 資料庫 (DB): 決議採用直接 clone 的方式複製資料庫，以確保數百張資料表的結構、關聯甚至寫死的設定值能完整保留，避免因重建而導致非預期錯誤。

2. 檔案儲存 (GCP Storage): 系統中用於存放保單、轉檔資料的 GCP Storage 也需要完整複製其結構與內容。

3. 程式碼與部署 (GitLab & CI/CD): 現有的 CI/CD 流程與環境緊密綁定，因此程式碼庫需要一併遷移。股感將協助 clone GitLab repo，再由羅賓斯科技修改 runner 設定，指向新的 GCP project。

4. 外部依賴: 新環境將產生新的對外 IP，必須向各家保險公司重新申請加入白名單，此為關鍵的前置作業。

三、商業條件與成本評估

此次拆分的主要商業驅動力，是實現羅賓斯科技與保代在財務與營運上的各自獨立。針對成本，會議達成以下共識：

  • 短期資源共用： 為加速 7/10 的上線目標，如簡訊、Email 等第三方服務的 API Key 與 Token 將暫時在新舊環境中共用，待系統穩定後再進行拆分。
  • 成本最壞情況評估： Leon 評估，在最壞的情況下，若新環境無法立即優化，可能需要短暫地支付一個月約 12 萬的全額基礎設施費用，直到舊環境的資源能被安全地關閉。
  • 帳務移轉： 拆分完成後，舊 GCP project 的帳務與所有權將明確移轉給保代方，羅賓斯科技僅需負擔新 project 的費用。

四、下一步與後續動作

會議確立了清晰的行動計畫與分工。由羅賓斯科技 CTO Leon 擔任技術總負責人，主導整個 GCP 環境的複製與遷移工作，並訂下 2026 年 7 月 10 日 為提供「富易達」測試環境的目標日期。CEO Evin 將負責商務溝通，向關係人（Stella）同步此重大決策，並啟動關鍵的 IP 白名單申請流程。股感的 Loki 則扮演顧問與支援角色，提供現有系統架構的專業知識，並協助處理 GitLab 遷移。原先針對單一 IAE 問題的修復工作，將被此一更全面的系統拆分計畫所取代。
