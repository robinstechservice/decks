1. 摘要重點 EXECUTIVE SUMMARY

一句話定位：loops 是「AI agent 自動迴圈 marketplace」— 把「人類反覆 prompt」換成「agent 自己跑 loop 直到搞定」。Slogan：「Stop prompting. Start looping.」

  • 作者：elorm（個人開發者、免費 + 廣告 + 社群捐款）
  • 受眾：用 AI coding 工具的工程師
  • 當紅迹象：頭牌「Ship PR Until Green」已被 copy 1,400 次

核心框架：什麼是 Loop？

每個 loop 包含 3 件事：

TRIGGER 觸發

啟動條件

手動 / 事件 (file change / commit) / 定時 (interval-based, e.g., 5 分一次)

FEEDBACK GATE 回饋閘

每輪檢查

跑 command 看真實輸出（例如 npm test、curl health endpoint），agent 依結果決定下一步

EXIT CONDITION 退場條件

明確的結束

「所有 CI check 過」「health endpoint 200」「max 10 次迭代」— 不會無限跑

2. 對羅賓斯科技的應用 APPLICATION TO ROBINSTECH

loops 本身雖然是 dev tool 平台，但「self-pacing loop with exit condition」這套思想 100% 適用羅賓斯保險科技 B2B 業務、且不限工程師。我用 4 個層次說明：

🟢 Layer A：5 姐妹 agent 內部（即刻可用）

這是最 obvious 的應用 — 我們 5 姐妹本身就是「agent」、loops 框架直接套：

Iris：圖卡 self-loop iter

已實踐！6/19 海賊王 hero v1-v23 就是 self-loop iter checklist 6/6 才 ship。可正式化為 iris-ship-image-until-passes-checklist.loop

Themis：QC verifier loop

對應 Independent Verifier — 5 姐妹任何對外 ship 前、Themis 不看 author rationale、只跑「事實 grep + 邏輯驗算」、過了才放行

Vena：合約 pre-commit guard

對應 Pre-Commit Guard — 合約 ship 前自動跑「機密數字檢查 + SOP/14 邊界 + Logo 合規」、任一掛就擋

Eos：CI failure watcher

對應 /loop 5m — 早報 pipeline 失敗自動讀 log → 修 → 重跑直到全綠（她已在做、可用 loops 語法正式化）

Calliope：deploy verification

對應 /loop 15m — GH Pages push 後 curl 200 + grep 字串 → 確認上線才回 ship 訊息

跨 sister：3-3-3 weekly retro loop

對應 interval-based — 每週日 chair 自動 trigger、5 sister 寫 3-3-3、Calliope 整合 ship Evin、退場條件：Evin 已讀

🟡 Layer B：保險業務 workflow（中期、需 1-2 個月）

  • Claims-Approval Loop：保戶報案後 agent 自動跑「文件齊全？OCR 通過？保額 ≤ NT$ 5 萬？無詐欺特徵？」全 ✅ → 即賠付。任一 ✗ → 給人工。退場條件 max 5 次來回、超過升級 supervisor。
  • Underwriting Verifier：核保時用 Independent Verifier — 另一個 agent 不看 sales 提交的客戶 rationale、只看「年齡 + 體檢 + 既往症 + 保額」cold check、過了才核準
  • Renewal-Reminder Loop：到期前 60/30/7 天 polling、自動 LINE OA push + 點開狀態回讀、續保完成 = exit。15 天無動作升級 agent 介入
  • Policy Compliance Watcher：金管會發新函令、agent 每 24 hr scan 主管機關公告、若涉及自家商品條款 → 觸發 Vena agent 跑「條款一致性 audit」loop

🟠 Layer C：3,000 業務員 SaaS（這正是羅賓斯產品 B 線）

把 loops 思想內嵌進業務員 SaaS：

  • 「成交直到」loop：給每位業務員一個自動 follow-up loop — 案件未結 → 每 3 天 LINE OA 提醒客戶 → 客戶回 / 業務員打勾 才退場、提供業務員「我這週 active loop 12 件」儀表板
  • 「保費收齊」loop：保費逾期 → 業務員 SaaS 自動 trigger 提醒 + 自動分流（小額 OK + 提醒、大額升級 supervisor）
  • 客戶 NPS-recovery loop：客戶評分 ≤ 7 分 → trigger 7 天內業務員 + agent 雙重接觸、retry max 3 次後升級主管

🔴 Layer D：API 中台 / 場景保險（C 線最值切入）

  • API health watcher /loop 5m：14 家產險合作 API 任一掛 → agent 自動 retry → 3 次 fail 切備援 → ping Leon + 客戶通知
  • API SLA verifier loop：每 24 hr 自動跑「過去 7 天 各 partner API 回應時間 + 錯誤率」、低於 SLA → 自動產 report ship partner CSAT
  • 場景保險「曝險自動化」loop：UBER 司機開始接單 → trigger 投保 → 收班 → trigger 退保 → 每分鐘 polling 司機 GPS、退場條件 = 司機收班 60 分

誠實 dissent（per 誠實 SOP）

loops.elorm.xyz 本身是 dev tool platform、不是 enterprise solution。直接「採用 loops 平台」對羅賓斯沒意義 — 我們不缺 dev loop、缺的是「把 loop 思想內嵌進保險業務流程」。所以建議 不註冊不用 loops 平台、但偷它的設計思想。 — Iris 評估

3. 如何開始 HOW TO START — 14-DAY PILOT

我建議 3 階段 14 天試行、由 Iris 主導，端午過後立刻啟動：

PHASE 1 · DAY 1-3 · LEARN
5 姐妹學 loops 框架
每位姐妹用「self-loop」語法重寫自家 1 個現有 workflow（例：Iris 圖卡 ship loop / Vena 合約 ship loop / Themis QC verifier loop / Eos 早報 polling loop / Calliope GH Pages verification loop）。寫成 .loop.md 檔放 ~/robinstech/shared/loops/
3 天、0 成本
PHASE 2 · DAY 4-7 · APPLY INTERNAL
內部 Layer A 全套上線
5 姐妹 loop 互相 cross-link、用 Vena 3-3-3 retro framework 每天測 1 個 loop、找出 false positive / false negative、迭代 spec。週末檢視「自動化省了多少 ping Evin 次數」、定量比較
4 天、0 成本
PHASE 3 · DAY 8-14 · PILOT 1 BUSINESS LOOP
選 1 個業務 loop 試跑
建議從 Renewal-Reminder Loop 開始（風險最低、ROI 最易量化）— 取現有 100 個續保到期客戶、跑 14 天、比對「loop 自動化 vs 業務員手動」續保成功率 + 工時節省。Day 14 ship 試行報告給 Evin 拍是否擴大
7 天、NT$ 0 額外成本（LINE OA 已有）
DAY 15+ · IF PILOT PASS
擴大到 Claims-Approval + Underwriting Verifier
這 2 個 loop 涉及保費 + 風險定價、需 Vena 法務預審 + Leon 系統整合、預估 1-2 個月 rollout。同時可寫進 P088 自介 v4「我們 AI loop 內建保險作業流程」差異化
2 個月

# .robinstech/loops/renewal-reminder.loop.md
goal: "續保提醒自動化、提升續保率 5%"
trigger: /loop 24h
max_iterations: 30  # 30 天 max

step_instructions:
  - query CRM: select customer where days_to_expire in [60,30,14,7,1]
  - push LINE OA: 對應天數的 template message
  - read: 客戶是否點開、是否回 / 業務員是否打勾「續保完成」

between_iteration_command:
  - check: SELECT COUNT(*) FROM renewals WHERE status='completed'

exit_conditions:
  - 客戶 status = renewed → DONE
  - 業務員手動 mark = handled → DONE
  - days_to_expire < 0 + 15 → ESCALATE to supervisor agent
