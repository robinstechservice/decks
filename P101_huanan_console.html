PART 03 · 摘要

會議摘要

重點摘要

(1) 會議目的與背景

本次會議由羅賓斯科技（Robins Technology）向華南產險營業五部提案其 Console 後台管理系統的使用方案。羅賓斯科技由 CEO Evin Lin 與業務發展 Matt 代表，向華南產險的珊珊進行產品演示。羅賓斯科技先前已與華南產險總公司簽約，但使用率不高，因此希望透過此次會議，將其服務導入分公司層級，提升合作效益。會議旨在展示 Console 系統如何透過 AI 技術解決產險業務中的效率痛點，並探討具體的合作模式。

(2) 羅賓斯提案核心：Console 站功能與價值主張

Matt 主導了 Console 平台的線上演示，核心功能聚焦於兩大主軸：

1. 即時車籍與保險資料查詢：
▸ 使用者僅需輸入「車牌號碼」與「車主身分證字號」，系統即可即時查詢並回傳多項關鍵資料。
▸ 車籍資料：包含廠牌代碼、詳細車型、出廠日期、領牌日期、引擎號碼等。系統能對應廠牌代碼，從保發中心的資料庫中拉取對應的詳細車型，解決同一車款有多種規格的識別問題。
▸ 重置價格：系統會自動帶出該車型的重置價格，這是計算車體險保費的關鍵基礎，免去人工查找的麻煩。
▸ 保險到期日：系統能同時查詢「強制險」與「任意險」的到期日，讓業務員能精準掌握客戶續保的時機，進行有效通知與推廣。

2. OCR 光學字元辨識與資料自動化 Key-in：
▸ 此功能旨在解決保險業務中大量文書的人工輸入痛點。使用者可將要保書的掃描檔（PDF 或圖片格式）上傳至系統。
▸ 系統會利用 OCR 技術自動辨識並解析文件中的所有欄位，包含要保人/被保人姓名、ID、保險公司、險種、業務員、生效日期、價格、車籍資料等，並將其結構化。
▸ 解析後的資料會並列顯示在原始文件旁，方便使用者核對。此功能可大幅縮短資料建檔時間、降低人為輸入錯誤率，並可處理單筆或多筆（批次）文件。

羅賓斯的價值主張是透過 AI 技術賦能，將產險業務員從繁瑣的行政工作中解放出來，專注於客戶服務與銷售，從而提升整體業務效率與準確性。

(3) 華南產險營業五部的需求 / 痛點

珊珊在會議中提出的問題，反映了華南產險在實務操作上的考量與痛點： ▸ 資料輸入的沉重負擔：珊珊明確表示，他們「每天都在 key-in」，證實了人工資料輸入是日常營運的一大痛點，對於能簡化此流程的 OCR 功能抱持興趣。 ▸ 車型識別的準確性：她特別關心系統如何精準識別特定車型。由於同一車款常有多種不同配備與價格的子型號（例如 Mondeo 有七八種），這會直接影響保費估算，因此系統能否提供準確的對應至關重要。 ▸ 系統整合與工作流程：珊珊關心解析後的資料如何與華南現有的系統對接。她理解到，最終理想的模式是透過 API 串接，將資料直接匯入公司內部系統，而非僅僅是匯出成 Excel 檔案再手動匯入。 ▸ 對新技術的實用性評估：雖然她認同 OCR 是未來的趨勢，但也務實地提出，對於大型保險公司而言，內部可能已有相應的處理流程，因此需要實際測試來評估此功能在華南工作流程中的確切效益。

(4) 雙方互動與技術討論

會議互動性高，珊珊針對演示內容提出多個實務問題，羅賓斯團隊也即時提供技術說明： ▸ 車型辨識機制：Evin 解釋，目前系統是透過演算法抓取機率最高的車型，但未來計畫改進為提供一個「區間」或選項，讓使用者能更精準地選擇。資料來源主要為保發中心的公開數據。 ▸ OCR 資料匯出與 API 串接：Evin 強調，OCR 解析出的資料欄位可以客製化。客戶不需接收所有辨識出的 100 個欄位，可以透過 API 設定，只抓取他們需要的 20 個欄位，直接對接到其內部系統，實現最高效率的整合。 ▸ 試用與反饋：雙方一致認為，最好的評估方式是讓珊珊親自試用。羅賓斯承諾會開設測試帳號，讓華南團隊能上傳實際文件進行測試，並根據使用體驗提供反饋。

(5) 共識 / 待議事項

▸ 共識： 1. 華南產險確認了提升資料處理效率的需求。 2. 雙方同意後續將由羅賓斯科技提供一個測試帳號，供珊珊及其團隊進行實測評估。 3. 實際操作與測試是評估此方案是否符合華南需求的最佳途徑。 ▸ 待議事項： 1. 測試帳號的具體權限與開通時間。 2. 若測試結果正面，後續的 API 串接規格、時程與商務合作細節。 3. 與華南產險協理級主管的會議時間需再行安排。

(6) 後續行動

1. 羅賓斯科技（Matt/Evin）將為珊珊開設 Console 平台的測試帳號。 2. 珊珊需提供 Email 給羅賓斯科技以利開設帳號。 3. Evin 將透過 LINE 將 Matt 的聯絡方式提供給珊珊，建立直接溝通管道。 4. 珊珊在取得帳號後，將進行內部測試，並向羅賓斯提供使用反饋。 5. Evin 將持續追蹤與華南產險協理的會議安排進度。
