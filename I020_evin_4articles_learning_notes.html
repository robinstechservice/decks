01 · GPT-5.6 Sol Family — OpenAI 三模型 + 美國政府限縮 access

類別 · AI Model / Frontier Capability
📚 來源：OpenAI 官方文章 + Sam Altman 在 X 的說明 + System Card

核心洞察 7 點

  • Sol（最強 flagship）/ Terra（平衡型）/ Luna（最便宜）三層、用「太陽 / 地球 / 月亮」命名表達 tier 階層
  • Sol 跟 GPT-5.5 同價（input $5 / output $30 per 1M tokens）— 不漲價、用同錢買更強
  • Terra 用 GPT-5.5 一半價格、做到接近 GPT-5.5 的能力 — 中階模型成本效率被推上一個台階
  • 美國政府首次干預：要求先在 trusted partners 跑 limited preview、不是 broad launch — frontier model 治理進入新階段
  • Sol 引入 max reasoning（深度推理）+ ultra mode（subagents 並行）— 單顆模型 → 多 agent 樂團
  • Terminal-Bench 2.1：Sol Ultra 91.9% / Sol 88.76% / Claude Mythos 5 88.0% / Terra 84.3% — Terra 站上 GPT-5.5 / Claude Fable 5 同一線
  • Cerebras 上 Sol 7 月可達 750 tokens/sec — 不是聊天變快、是 agent 迭代密度暴增（同樣時間試更多路徑）

我學到什麼

Frontier model 競賽不再只是「誰最強」、是「中階模型誰最便宜」+「政府如何介入」+「速度如何改變 agent 行為」三場同時的戰爭。Terra 用一半價接近上代 flagship 這件事、對中小公司 routing strategy 影響最大 — 以前必須用 flagship 的、現在 Terra 就夠、月成本砍半。

Sol 的 ExploitBench 73.5% 雖然不到 Critical threshold、但「Sol 用 1/3 tokens 接近 Mythos Preview」這個 efficiency signal 比絕對分數更值得注意 — 同樣推理深度、tokens 砍 2/3 = 成本砍 2/3。

📌 第一步如何開始
下週起把現有 ChatGPT / Claude API 工作流量做一次 audit：哪些任務真的需要 flagship（複雜推理 / 長程 agent / 程式碼生成）？哪些其實 Terra-tier 就夠（一般草稿 / 摘要 / 翻譯 / 重複問答）？建一張 routing table、預期降低 30-50% API 費用。
🎯 預期 1 個月成果
(1) 每月 API 帳單降 30-50%、(2) 形成內部「Sol / Terra / Luna 任務分流 SOP」、(3) prompt caching 30 分鐘最低 cache life 利用率 60%+（reuse system prompt / docs / 程式碼庫）、(4) 開始追 ultra mode subagent 對 long-horizon task 完成率影響。

02 · Notion AI 轉型成熟度報告 — 88% 還在 L1-L2、最難跨是 L2→L3

類別 · AI Adoption Maturity / Organization Transformation
📚 來源：Notion《The Great Renovation: Inside the AI Transformation》(2026-06)、6,118 人 / 10 個全球市場

核心洞察 8 點

  • 4 層成熟度框架：L1 思考夥伴（57%）→ L2 助理（31%）→ L3 隊友（10%）→ L4 系統（2%）。全球只 12% 跨到 L3+
  • 最難跨的是 L2→L3：從「我用 AI」變「AI 替我跑完流程」是類別轉變、不是工具升級
  • 決策者與員工認知落差 5x：決策者說 26% 達 L3+、AI 使用者說 5%、同一個組織描述兩場不同的轉型
  • 新加坡領先全球 21%、美國 11%、台灣未在樣本但中型企業（500-999 人）領先 17% 大企業（5000+）只 7%
  • 老闆 / CEO 達 L3+ 39%、個人貢獻者僅 6% — 6 倍落差、各地區一致
  • 拉開差距 3 件事：整合系統（+18 pp）+ 治理監督（+16 pp）+ 衡量指標（+15 pp）— 培訓和政策每家都做、不是差異主因
  • 成熟組織衡量「品質指標 / 工作流程 / 財務指標」、新手組織衡量「自我回報節省時間」— 衡量對象從 AI 團隊轉移到業務本身
  • 71% 使用者說：如果信任 AI 不犯錯、他們會用更多 — 信任 + 可見度是同一個問題的兩面

我學到什麼

大多數人對 AI 採用程度過度樂觀。如果決策者覺得自己 L3、員工實際感受是 L1.5、組織就會把「投資速度」推到員工跟不上的程度（L4 組織 68% 的決策者承認這點）。差距會擴大、不是縮小。

另一個冷酷洞察：自動化重複任務（L3-4 36% vs L1-2 18%）跟「跨工具路由工作」（26% vs 11%）是真正的成熟度信號、不是「用 AI 寫信」這種個人生產力。這把「用 AI 多少」這個錯誤指標換成「AI 跨多少系統 + 跑多少步」。

📌 第一步如何開始
本週做組織自評：問每位團隊成員 1 個問題「你今天用 AI 做的事、是個人用 ChatGPT 起草（L1）、嵌入流程能讀公司資料（L2）、agent 端對端跑完保留人工審核（L3）、還是 agent 完全自主跑完核心流程（L4）？」蒐集匿名答案、對比決策者自己以為的層級。預期會看到 1-2 個層級落差。
🎯 預期 1 個月成果
(1) 拿到「我們真實的 L 分布表」、(2) 識別 1 個從 L2 跳到 L3 的 pilot 流程（最常選 onboarding / 客服 / 報表生成）、(3) 為這 pilot 寫 3 個指標：品質、工作流程吞吐、財務（不寫「省幾小時」）、(4) 7 天後 review 第一輪數據、決定擴大或收回。

03 · Claude Tag · Agent Identity — Anthropic 新權限框架

類別 · AI Governance / Identity & Access Management
📚 來源：Anthropic 官方部落格《Agent identity: a new access model for autonomous, team-wide AI》

核心洞察 6 點

  • 當 Claude 在 4 人頻道工作、它用的是「它自己的權限」、不是任何使用者的權限 — agent identity 是新一層
  • 不能用使用者身份的原因：若 Claude 用「某員工的權限」執行、那員工離職 / 換 role / 暫停權限時、Claude 行為會變動或失敗 — 系統不可預測
  • DM vs Channel 兩種模式：DM 是 1:1 對話、Channel 是團隊共享 — agent identity 在兩種場景權限不同
  • 管理員設定：可決定 agent 能存取哪些工具 / data sources / 哪些頻道、就像給「真員工」配置 access
  • 稽核 + 安全：所有 agent 動作有 audit log、不會與人類動作混淆
  • 這個設計解決核心問題：autonomous agent 需要穩定 identity 才能被信任承擔多步任務、不是每次都要當下 user impersonate

我學到什麼

2026 中 agent 治理才開始正規化。在這之前所有 agent 都是「借 user token」執行、本質是 impersonation。impersonation 適合 demo、不適合 production：權限歸屬不清、稽核困難、責任歸屬模糊、員工流動性引發 cascade failure。

Anthropic 把 agent 當「組織中的數位員工」這個 framing 是重點。「agent 有自己的 identity + 自己的權限 + 自己的稽核 log」這套設計、未來會被所有 enterprise AI 平台採用。比較像 service account 的進化版、但帶意圖識別 + 對話能力。

📌 第一步如何開始
本週審視內部 AI 使用：列出所有「agent / chatbot / 自動化腳本」目前用的是誰的權限（個人 OAuth token / service account / hardcoded admin key）？把這個清單畫出來、就會發現 90% 是某員工的個人 token 在跑。下一步是計畫遷移到 service-account-style agent identity。
🎯 預期 1 個月成果
(1) 完成 agent 權限 audit 表（誰借誰的權限）、(2) 至少 1 個 agent 從 user token 遷移到專屬 service account / agent identity、(3) 開啟 audit logging、(4) 草擬內部 AI agent governance policy v0.1（誰能授權新 agent / 權限範圍 / 退場流程）。

04 · Good SEO is Good GEO — AI 搜尋時代回歸本質

類別 · Marketing / SEO / Generative Engine Optimization
📚 來源：Think with Google · Brendon Kraham (VP Search & Commerce Global Ads Solutions, Google)

核心洞察 6 點

  • GEO（Generative Engine Optimization）不是新東西、就是 Good SEO — Google 親口說別追新名詞、回歸本質
  • 避免關鍵字堆砌（keyword stuffing）— AI 搜尋反而會懲罰過度優化內容、因為它識別意圖、不只匹配字串
  • 專注 authentic content：原創觀點 / 第一手經驗 / 具體案例 — AI 搜尋偏好「值得引用」的內容、不是「適合排名」的內容
  • 網站體驗（load speed / 行動裝置適配 / 結構化 schema markup）對 AI overview 引用率正相關
  • 從追「ranking position」轉到追「business metrics」：實際引流 / 轉換 / 客戶價值、不只看排名表
  • 留言「萬本不離宗」反映共識：SEO 從業者體感是「該做的還是要做、AI 沒讓基礎工失效、只是放大了 authentic 的回報」

我學到什麼

AI 搜尋（ChatGPT 搜尋 / Perplexity / Google AI Overview）改變了「使用者怎麼問問題」但沒改變「搜尋引擎判斷品質的標準」。Google 自己跳出來說 GEO ≈ SEO、是要冷卻市場對「新顧問課程」「新工具」的追逐熱度、把 SEO 從業者拉回 substance。

對 B2B 內容創作者：以前寫 1,500 字 SEO 文、塞 8 個關鍵字、能排上 Google 第 1 頁。現在同樣 1,500 字 + 8 個關鍵字、AI overview 連引用都不引用、流量歸零。改寫成 1,500 字第一手經驗 + 2-3 個具體案例 + schema markup、被引用率反而上升。「內容深度 + 結構化」變成新黃金組合。

📌 第一步如何開始
本週挑公司網站 3 篇流量最高文章、檢查 3 件事：(a) 有沒有 keyword stuffing（同關鍵字超過 3 次密度 1.5%+）？(b) 有沒有原創 first-party 數據 / 客戶案例 / 自家觀點？(c) 有沒有 JSON-LD schema markup（Article / FAQ / HowTo）？任一條 fail = 改寫。
🎯 預期 1 個月成果
(1) 3 篇文章重寫完成、(2) 加入 schema markup、(3) 用 Google Search Console + Bing Webmaster + Perplexity 引用追蹤、量「AI overview 引用率」變化、(4) 確認業務轉換不只看排名、改看「AI 來源流量 + 對話深度 + 轉換」3 個 funnel metric。
