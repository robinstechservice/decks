2. 深評原因 1000 字DEEP-EVAL RATIONALE

這是我從 6/19 接小組長以來、看到「最直接解我們具體痛點」的 skill / spec。不是空泛「可能有用」、是「我今天就在踩、它今天就能解」的對應。

痛點背景：羅賓斯 4 個月來反覆踩的「品牌漂移」陷阱

從 4 月底我開始畫圖卡，到 6/24 海賊王 hero scene 22 次 reroll，中間經歷了：5 姐妹介紹卡 v1→v7 lock（中間每版 Nano Banana 把 navy 跑成紫、把 gold 跑成橘）、端午海報 9 變體（每張要重申一次「Robi 是橘狐」）、Anthropic 字幕影片 V001 包裝（Robi logo 圓框大小自動漂移 ±10px）、Matt Console demo 60s 版（黑底字幕框圓角從 8px 變 12px 變 16px）。共同根因：視覺 spec 用「prose 文字」傳給 AI 工具、AI 每次理解不同。每次 reroll 直接成本 NT$ 1.2 + 我 3-5 分人工 + Evin 看到不一致版被打回。

design.md 為什麼是對的解

它把「視覺 spec」從「我寫一段話描述」升級成「YAML token + Markdown rationale 雙層格式」。前者讓 AI agent 把每個顏色 / 字級 / 圓角讀成「精確值」、不是「大概紫色」；後者保留「為什麼用這個值」的 designer 邏輯。Google labs 親自定 spec、18.1k stars 已驗證共識。對 Iris 的具體 win：

  • color tokens 精確化：寫 primary: "#0F1F4D" 而非 prose「深藍色」。每次 Nano Banana / Gemini 出圖前 system prompt 注 robinstech.design.md → 顏色漂移 -90%
  • typography 系統化：h1 / h2 / body / cta 各層字級 + 字重 + 字距 全部寫死。下次劉順仁書摘第 19 頁 chip 不會自己變 12px → 修溢出時間從 30 分降到 0
  • spacing scale 統一：margin / padding / gap 都從 spacing scale 引用、不再「我覺得 28 大概夠」
  • rounded scale 統一：所有圓角從 rounded: {sm:4, md:8, lg:12} 引用、不再 8 / 10 / 12 / 16 自由跑
  • components 預定義：button-primary / card / chip / hero-banner 各自的 token 組合定義一次、所有姐妹 build 用同一套
  • lint + diff CLI：寫 `design.md lint generated/anyimage.html` 自動檢查我輸出有沒有踩雷、`design.md diff old.md new.md` 看品牌升級時哪些 token 變了

具體落地路徑（4 步、48 hr 內可跑）

Step 1（90 min）：把現有 P088 自介 v4 / 5 姐妹介紹 baseline / 端午海報 baseline 三套素材的視覺 token 反推出來、寫成 robinstech.design.md（含 navy / gold / Robi 橘 / Bao 白 / 思源黑體 TC / Montserrat / 18pt 最小字級 / spacing scale 等）

Step 2（30 min）：用 npx @google/design.md lint 驗 spec 內部一致 + WCAG 對比度合格

Step 3（60 min）：把 robinstech.design.md 內容（YAML 段）注入 scripts/generate_image.py 的 system prompt、Nano Banana 出圖前必先讀

Step 4（持續）：每次 Evin lock 新 baseline（如 Iris baseline v2、festival baseline v2）→ 更新 design.md → diff 紀錄 token 演進 → 5 姐妹同步

誠實 dissent（per honesty SOP）

design.md 不是萬靈丹、3 個誠實限制：

  1. 不解 CJK 字元渲染問題：spec 只覆蓋視覺 token、不管字元 encoding / font subsetting / OpenType。我們「中文字打錯」「字級飄」這類 Nano Banana 本身限制、design.md 救不到。仍需 Recraft V3 補位（per I089）
  2. Alpha 階段：v0.3.0、spec 可能變、需追 Google 更新
  3. 無 agent-specific 整合：spec 是 model-agnostic、要靠我把 robinstech.design.md 注 prompt + 自行驗證輸出有沒有套用、不是 plug-and-play

為什麼是 ⭐⭐⭐⭐ 而非 ⭐⭐⭐⭐⭐

扣 1 星因為：(a) alpha 階段、未來 spec 變 lock-in 風險、(b) 中文字仍要 Recraft 補、(c) 整合需要我手動寫 robinstech.design.md（不是裝完就有）。但這 3 點都是「我可以接受 + 1 週內可緩解」的 cost、整體 ROI 仍是 6/19 以來 top 1。

4. 如何開始HOW TO START

# Day 1 - 安裝 + 反推現有 baseline
npm install -g @google/design.md
mkdir -p ~/robinstech/shared/design
# 寫 robinstech.design.md（navy/gold/Robi橘/思源黑體 TC/Montserrat/spacing/rounded/typography...）
nano ~/robinstech/shared/design/robinstech.design.md

# Day 1 - 驗 spec 內部一致 + WCAG 對比度
npx @google/design.md lint ~/robinstech/shared/design/robinstech.design.md

# Day 2 - 注入 generate_image.py system prompt
echo "# Brand spec (token-based, MUST follow)" >> scripts/system_prompt.txt
cat ~/robinstech/shared/design/robinstech.design.md >> scripts/system_prompt.txt

# Day 2 - 試跑：用 spec 出端午海報 baseline v2、對比舊版
python3 scripts/generate_image.py "端午 baseline v2 with spec" --out test.png

# Day 3 - export Tailwind / W3C tokens 給未來 landing page 共用
npx @google/design.md export --format json-tailwind robinstech.design.md > tailwind.tokens.json
